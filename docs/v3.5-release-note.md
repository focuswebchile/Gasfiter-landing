# Release Note V3.5

Fecha: 2026-03-02  
Estado: Cerrado (estable en staging)

## Objetivo de V3.5
Reducir complejidad del panel de edición y mejorar el flujo real de trabajo para `editor` y `owner/admin`, sin romper contratos de backend ni shape JSON de `settings`.

## Alcance implementado

### 1) Workspace enfocado
- Layout desktop-first con editor central como foco.
- Sidebar clara por grupos de contenido/configuración.
- Herramientas avanzadas restringidas por rol.

### 2) Overlays bajo demanda
- Vista previa en overlay.
- Diff en overlay (sin panel derecho permanente).
- Estado compartido en padre, sin duplicación de store.

### 3) Botonería y permisos por rol
- `owner/admin`: flujo completo (publicar, rollback, herramientas avanzadas).
- `editor`: edición + guardar borrador + solicitar publicación.
- Flujo `request-publish` operativo con endpoint dedicado.

### 4) Microcopy y estado de flujo
- Mensajes guiados: **Completar → Revisar → Publicar**.
- Barra de progreso global del flujo.
- Copy simplificado para perfiles no técnicos.

### 5) QA responsive
- Ajustes de tablet/móvil grande para sidebar, formularios, overlays y toasts.
- Sin cambios de lógica de negocio ni de reglas backend.

## Seguridad y consistencia
- RLS habilitado y saneado en tablas públicas del CMS.
- Sin cambios al contrato de `/api/sites/:slug/settings`.
- Compatibilidad preservada con `save-draft`, `publish`, `rollback`.

## Validación ejecutada (staging)
- Lint: OK.
- Build: estable en entorno real/deploy.
- Flujos probados:
  - Editar → Guardar borrador.
  - Solicitar publicación (editor).
  - Publicar (owner/admin).
  - Rollback (owner/admin).
  - Preview + diff bajo demanda.

## Riesgos conocidos (no bloqueantes)
- Notificación por email en `request-publish` depende de configurar:
  - `RESEND_API_KEY`
  - `RESEND_FROM_EMAIL`
- Si no está configurado, el flujo sigue funcionando, pero sin envío de correo.

## Pendientes propuestos para V3.6
- Modal interno para “Solicitar publicación” (reemplazar `window.prompt`).
- Historial de solicitud de publicación visible por sitio.
- Mejoras de auditoría (quién solicitó, cuándo se resolvió, SLA).
- Optimización puntual de queries de mayor frecuencia observadas en Supabase.
