# T8.0 — Guardrails + Baseline Visual (Editor CMS ABCIS)

Estado: `ready`
Tipo: `UI visual only` (sin cambios de lógica de negocio)

## 1) Objetivo
Crear límites formales para el refactor visual del editor CMS y congelar un baseline de referencia para evitar regresiones funcionales y de flujo.

## 2) In/Out Scope
### En alcance
- Orden visual del panel (`layout`, `spacing`, `jerarquía tipográfica`, `colores`, `botones`, `microcopy`).
- Consistencia de componentes UI entre vistas (`sections`, `items`, `style`, `versions`, `members`).
- Eliminación de textos legacy visibles en UI.

### Fuera de alcance (prohibido en T8)
- Cambios de API/endpoint, schema o payload.
- Cambios de permisos/roles.
- Cambios de validación P0/P1.
- Cambios de lógica de `save draft`, `publish`, `rollback`, `request publish`.
- Cambios de estructura de datos CMS.

## 3) Guardrails técnicos obligatorios
1. No editar archivos en `src/app/api/**` salvo bug crítico aprobado.
2. No editar `src/lib/publish-requirements.ts` durante T8 visual.
3. No editar contratos de datos en `src/lib/settings-schema.ts` durante T8 visual.
4. En `src/components/staging-workflow-panel.tsx`, limitar cambios a:
   - clases CSS
   - estructura visual (markup) sin alterar handlers ni side-effects
   - textos de interfaz
5. Si un ajuste visual requiere cambio lógico, se deriva a ticket separado.

## 4) Baseline visual a congelar (antes de T8.1+)
Capturar evidencia de:
- Vista `sections` con checklist y bloque de advertencias.
- Vista `items` con cards de servicios/faq.
- Vista `style` con branding y uploads.
- Vista `versions`.
- Vista `members` (owner/admin).
- Estado error de publicación P0 (alert rojo + acciones “Ir a ...”).
- Estado éxito (toast/estado guardado/publicado).

## 5) QA mínimo que no se puede romper
1. Guardar borrador funciona con contenido incompleto.
2. Publicar bloquea P0 con mensaje claro.
3. Botones “Ir a ...” navegan a sección correcta.
4. `request publish`, `rollback`, `diff` siguen operativos.
5. Build de producción sin errores.

## 6) Definición de terminado de T8.0
- Guardrails documentados y aceptados.
- Baseline visual capturado y guardado.
- Checklist de validación listo para usar en T8.1–T8.5.
- No hay cambios funcionales introducidos.

## 7) Protocolo de ejecución para T8.x
Orden oficial:
1. T8.2 Layout
2. T8.1 Colores
3. T8.3 Jerarquía
4. T8.4 Botones
5. T8.5 Microcopy

Regla de merge:
- cada sub-ticket en commit aislado
- con build verde y smoke rápido al cierre
